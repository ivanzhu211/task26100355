# planadjust — 门店销量预测人工调整与层级分摊

Go 库，供上层补货计划服务调用（无接口层）。一个 `Service` 实例对应一个门店，
数据持久化在 SQLite（纯 Go 驱动 `modernc.org/sqlite`，无外部服务依赖）。

## 模型

- 计划期固定 91 天（13 个自然周，从周一开始）；最小格子 = 1 个 SKU 的 1 天，非负整数。
- 统计预测由外部模块整版提供、整版更换。
- 一条调整 = 范围（商品维度：全店/品类/SKU × 时间维度：计划期/周/天）+ 目标合计。
- 调整状态：`active` 生效、`voided` 作废、`superseded` 被取代、`conflict` 冲突、`withdrawn` 已撤销。

## 分摊规则

- 被新范围完全包含的更早生效调整：格子原样不动；其余格子按当前值比例分摊
  （全为 0 时平均分），每格为精确份额向下/向上取整，合计分毫不差。
- 存在包含新范围的更早生效调整时，由最近的包含者在新范围之外、
  其他更小生效调整之外的格子上按当前值比例反向消化，保证其合计不变。
- 相交但互不包含 → 旧调整作废；范围完全相同 → 旧调整被取代。
- 任何时刻计划值 ≡ 从当前统计预测出发按提交顺序重放所有生效调整的结果
  （撤销、更换预测后通过重放维持该不变量）。
- 不可满足（目标小于冻结部分合计、消化格不够减、有量无格可动）→ 拒绝提交，
  计划值与所有调整状态完全不变；重算中才发现的旧调整不可满足 → 标为冲突。

## 用法

```go
svc, _ := planadjust.Open("store123.db")
defer svc.Close()

svc.Init(monday, skus)                 // 一次性初始化：起始周一 + SKU 清单
svc.ReplaceForecast(forecast)          // map[sku][]int64，91 个非负整数，整版更换

adj, err := svc.Submit(scope, 12000)   // err == planadjust.ErrInfeasible 表示被拒绝
svc.Withdraw(adj.ID)                   // 撤销，触发重算

sum, _ := svc.SumPlan(scope)           // 任意范围调整后合计
fsum, _ := svc.SumForecast(scope)      // 任意范围统计预测合计
v, _ := svc.PlanCell("SKU001", 15)     // 单格查询（day 为 1..91）
for _, a := range svc.Adjustments() {  // 全部调整及状态
    fmt.Println(a.ID, a.Scope, a.Target, a.Status)
}
```

进程重启后 `Open` 同一路径即可恢复：计划值由统计预测与生效调整确定性重放得出。

## 设计要点

- 生效调整的范围构成层叠族（两两嵌套或不相交），因此每条调整有唯一的最近包含者，
  被包含的子调整两两不相交，其格子合计恒等于各自目标值。
- 取整采用累计舍入：每格恰为精确份额的下/上取整，合计精确，且确定性可重放。
- 计划值常驻内存（45.5 万格 int64）并维护品类×天、全店×天聚合，
  任意范围合计查询为 O(91)，与调整条数无关。
- 提交不引起作废/取代时增量应用；作废、取代、撤销、更换预测时全量重放。

## 测试

```sh
go test ./...
```

覆盖：长随机操作序列（嵌套/交叉/同范围/撤销/换预测，每步校验生效调整合计精确、
格子非负、计划值与重放逐格一致）、拒绝前后状态逐项不变、重启恢复、
满规模（5000 SKU / 60 品类 / 500 条生效调整）性能：

- 单条提交（不作废他人）：< 10 ms（要求 2 s）
- 任意范围合计查询：< 0.1 ms（要求 50 ms）
- 撤销/更换预测重算：< 100 ms（要求 30 s）
